- **`captures.retry` is not key-aware (canonical-accounts follow-up)** — `retry` (packages/backend/convex/captures.ts:119) deliberately preserves `workspaceId`/`sessionId`/`deepLink` for idempotency, but if the user swapped their Conductor API key to a different account since the original submit, the preserved workspace belongs to the *old* account: the retry's orphan-adoption/`sendMessage` calls 403/404 and the capture re-fails terminally. Fix: before rescheduling, probe `getWorkspaceStatus` with the current key (needs an action, so restructure `retry` to schedule a `pipeline.prepareRetry` internal action); on auth/404 clear `workspaceId`/`sessionId`/`deepLink` and remap `projectId` by name against the fresh project cache (or fail with guidance) so the retry re-creates under the current account. The new C2 project-visibility guard (pipeline.ts step 3·0) already covers the *fresh*-submit variant; this covers retry.
- **History-row Conductor provenance** — true "workspace not accessible from your Conductor app" is a client-side fact (which account the Mac Conductor app is signed into), invisible to the backend — the stored key can always open the workspace it created, so no backend probe detects the mismatch. Weak but cheap mitigation: on the History row detail, show provenance (key last-4 via `settings.get`, project `gitRemote`) and a "Can't find this workspace in Conductor?" help note explaining the two-account failure mode, shown after the user opens an `agentWorking`/`ready` row. Complements the C1 Settings project-set display shipped alongside the C2 guard.

- **Session-expiry robustness (Phase C follow-up to the ID-token-refresh fix)** — the core fix (PR bumping to 1.0.8) makes `Auth0AuthProvider.currentIdToken()` decode the ID token's `exp` and force `CredentialsManager.renew()` when it's within a 5-min leeway, closing the ~10h→24h dead window where an already-expired ID token was handed to Convex (root cause of "Your session expired. Sign in again"). Deferred hardening: (1) **reset `consecutiveAuthDeferredDrains` on a successful drain** — today it resets only on an auth *state transition* (`WhistleApp.swift:257`), never on success, so "consecutive" is really cumulative-per-session and a few stale-token deferrals plus one transient blip escalate to `.reauthRequired`; add an `onDrainSucceeded` hook from `SyncEngine`. (2) **Silent recovery before `.reauthRequired`** in `AuthController.handleTokenRefreshFailure()` (one `renew()` + re-attach + `usersEnsure()` before surfacing the sign-in UI). (3) **Re-attach on `.notAuthenticated`** — add `refreshAuthAttachment()` (= `authGate.reset()` + `ensureAuthAttached()`) to `LiveConvexService`, invoked from the first deferral, to re-seed convex-swift's bridge token and neutralize its upstream `try?` stale-token fallback (`ConvexMobile.swift:219`); note `authGate.reset()` is epoch-aware after PR #22. **Already done, do not re-implement:** "don't count attach *timeouts* as auth failures" — PR #22's KTD6 shipped this; attach timeouts now throw `.requestFailed("auth attach timed out")`, only genuine token rejection throws `.notAuthenticated`. (4) **Serialize in-flight renewals against session transitions** — the `sessionGeneration`/`lastLogoutGeneration` guard in `Auth0AuthProvider` makes single-call sign-out final and stops the account-switch session-wipe, but a *straggler* `renew()` from a previous session can still complete off-actor (Auth0's `CredentialsManager` persists on success outside our actor) and re-store — resurrecting a signed-out Keychain, or overwriting a freshly-logged-in session's credentials — before its `discardingIfSignedOut` check runs. Fully closing this needs tracking the in-flight renewal `Task` and cancelling/awaiting it on `login()`/`logout()` (or funnelling all Keychain writes through the actor). Narrow race (requires a slow/retried renew concurrent with a transition); PR #23 review, security P2.
